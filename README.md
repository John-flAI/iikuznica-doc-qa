# Агент ответов на вопросы по корпоративным регламентам

Хакатон «ИИкузница» 2026 · задача №1 · трек «Аналитик данных».

Агент отвечает сотрудникам на вопросы по регламентам **только по найденным пунктам регламентов** (кратко, без добавления
фактов) и показывает источник — раздел, пункт, подпункт. Если ответа нет — не выдумывает, а заводит запрос в службу
качества: сотрудник видит карточку запроса с одной кнопкой «Отправить». Если вопрос допускает разные ответы — уточняет. После ответа службы качества — пополняет
базу знаний. Регламент — утверждённый документ, он главнее; ответ службы качества — консультация
о том, как применять его нормы (позиция заказчика, Q&A 27.11.2026).

**Стенд:** <https://docii.aized.ru> (второй адрес — <https://iikuznica.aized.ru>) — демонстрационный: до 60 вопросов в час
с одного адреса. Вход — страница с заранее заполненными почтой и паролем («Войти»); в доке под чатом — тема (тёмная и светлая),
оформление («Аврора» и «Слэк»), показ тестовых инструментов и выход.

## Что уже работает

- **Импорт регламентов.** DOCX разбирается на разделы, пункты и подпункты; номера пунктов
  восстанавливаются из разметки Word. Каждый абзац получает адрес и дословный текст. Импорт идёт командой
  при построении индекса; загрузки документов через веб-интерфейс в прототипе нет.
- **Поиск.** Два канала — по словам (BM25, леммы, глоссарий заказчика) и по смыслу (эмбеддинги) —
  слитые обратными рангами. Отдельно выдаётся лучший ответ каждого регламента: так видно, где
  дирекции отвечают на один вопрос по-разному.
- **Агент.** Модель решает: ответить, уточнить или признать, что ответа нет. Решение проверяется кодом:
  в ответ проходят только найденные фрагменты; если регламенты отвечают по-разному, агент уточняет.
- **Текст ответа.** Модель пишет связный ответ только по выбранным пунктам; код сверяет числа и
  сокращения с пунктами, вторая проверка — модель-судья. Не прошло — ответ показывается пунктами дословно.
- **Общение не по регламентам.** Приветствие, благодарность и «кто ты» распознаются словарём, без
  обращения к модели. Остальное решает модель: короткий вежливый ответ и возврат к регламентам, после
  двух подряд — «отвечаю только по регламентам». В службу качества уходит только рабочий вопрос;
  если близкие фрагменты нашлись, болтовкой вопрос не считается.
- **Лимит стенда.** Стенд демонстрационный: вопросов в час с одного адреса — не больше `ASK_LIMIT` (в коде по умолчанию 20,
  на публичном стенде задано 60), лимит написан на странице. Адрес — из `X-Forwarded-For` прокси, IPv6 считается сетью /64.
- **Изоляция по адресу.** Аккаунт создаётся по адресу сотрудника — тому же, что у лимита: каждый видит только свои
  диалоги, свои запросы в службу качества и свою аналитику; чужая сессия, чужой запрос и чужая запись базы знаний
  не существуют (404). Ответ службы качества попадает в базу знаний и ищется только у того, кто задавал вопрос.
  Сотрудники за одним адресом (NAT) видят одну систему.
- **Настройки.** Вкладка правой колонны из трёх блоков: «Модель», «Стенд и API» (адрес стенда, провайдер каждой модели, лимит)
  и «Почта». После ответа службы качества колонна сворачивается сама через полторы секунды.
- **Переключатель моделей.** На вкладке «Настройки» — кнопки-переключатели открытых моделей (по умолчанию
  Qwen3.5-122B-A10B — укладывается в 128 ГБ); выбор действует сразу во всех чатах, хранится в сессии и в браузере, каждая модель отвечает через своего клиента.
- **Несколько чатов.** Вкладки в шапке («+ Новый чат», переключение, переименование и закрытие правой кнопкой) хранятся в браузере
  и переживают обновление страницы; у каждого чата свой диалог и своя память, закрытый чат ведёт себя как несуществующий,
  данные остаются (`GET /api/sessions`, `POST /api/session/{id}/name`, `DELETE /api/session/{id}`).
- **Тесты.** 176 проверок: инварианты разбора (каждая цитата дословно есть в исходнике), вопросы
  сотрудника другими словами (нужный пункт в топ-3 у всех 16), логика агента и повторов модели,
  ограждения решений (лишние уточнения, повторный переспрос, согласованность регламентов, полные кнопки
  уточнения), служба качества, общение не по регламентам, лимит по адресу, маршруты стенда, лимиты длины,
  телеметрия клиента модели, переключатель моделей, изоляция по адресу, несколько чатов, почта и фиктивный вход,
  нечитаемый ответ модели, сбой сервера эмбеддингов, дедлайн серии вызовов.
- **Аналитика и телеметрия.** По каждому вопросу — маршрут, время и токены; по каждому обращению к модели —
  шаг (решение, текст, судья), модель и токены. Страница «Статистика» (`/analytics`, `GET /api/analytics`)
  показывает вопросы по маршрутам, средние время и токены, запросы службы качества по статусам и вопросы
  без ответа; `GET /api/weekly` собирает из них предложение «что внести в документацию». Разговор не по
  регламентам считается отдельно и в стоимость рабочего вопроса не попадает.
- **Устойчивость.** Сервер модели недоступен или ответил нечитаемо — сотрудник видит найденные пункты
  дословно и причину, без выдуманного ответа; серия вызовов ограничена по времени; при сбое сервера
  эмбеддингов поиск работает по словесному каналу.
- **Иерархия источников.** Утверждённый регламент главнее: ответ службы качества — консультация о том, как
  применять его нормы. Если они расходятся, ответ опирается на регламент и говорит о расхождении; карточка
  ответа службы качества помечена как консультация. Расходятся сами регламенты — агент не выбирает, а
  уточняет подразделение.
- **Конфиденциальность.** Исходящие соединения — только к серверу модели и серверу эмбеддингов; интерфейс
  без внешних ресурсов, ключи только в окружении. Для внутренних регламентов решение рассчитано на
  изолированный контур: сервер модели — любой OpenAI-совместимый, включая локальный (vLLM, Ollama), а
  эмбеддинги BGE-M3 уже считаются локально. Модели, укладывающиеся в 128 ГБ, — в каталоге стенда.

## Вход и почта

Вход фиктивный: страница входа открывает стенд от имени сотрудника — почта и пароль-заглушка заполнены заранее, изменить их
нельзя, сервер ничего не проверяет (`POST /api/login`). Три фиксированные роли с готовыми адресами заданы в `ACCOUNTS`
в `app/config.py` (список — `accounts` в `/api/health`): «Сотрудник» `client1@docii.aized.ru`, «Служба качества»
`s.kachestva@docii.aized.ru` и агент «ДокИИ» `agent@docii.aized.ru`. Ящик службы качества — вкладка «Служба качества»
правой колонны, ящик сотрудника — вкладка «Почта клиента» (обе — тестовые инструменты: на стартовом экране не видны,
показываются кнопкой тестовых инструментов; ящик службы качества открыт всегда на экране `/qc`); блок «Почта» на
вкладке «Настройки» — адреса стенда и признак отправки.

Агент — почтовый посредник между сотрудником и службой качества. Письма — четыре, в момент уже
существующих действий: при отправке запроса агент шлёт вопрос службе качества («Вопрос в службу
качества № N») и уведомление сотруднику («Ваш вопрос передан в службу качества, № N»); при ответе
служба качества отвечает агенту («Ответ службы качества № N»), и агент передаёт ответ сотруднику
(«Ответ на ваш вопрос № N»). Каждое письмо сохраняется в базе и доступно ящикам роли через
`GET /api/letters?role=…` и `GET /api/letter/{id}` (изоляция та же, что у запросов: чужие письма
не существуют). Если задана переменная `MAIL_SMTP` (`host:port`), письма уходят по SMTP — без TLS
и без аутентификации, таймаут 3 секунды; ошибка отправки не ломает действие, письма помечаются
не доставленными (`delivered`). На стенде в docker письма принимает mailpit (`deploy/compose.yml`);
локально без `MAIL_SMTP` письма только сохраняются в базе.

(последние прогоны Qwen и gpt-oss — с ограждениями решений, у GLM — до и после); модель от прогона к прогону гуляет,
поэтому у каждой — несколько прогонов:

|---|---|---|---|---|

| GLM-4.7-Flash (Z.ai) — снята со стенда | 23 из 31 | 9,3 | ≈3 630 | судья не пропустил 13 текстов из 31 (7 отказов, 6 переписано) |

`/api/health` называет модель по умолчанию (`model`), каталог (`models`) и модель, которая реально ответила
на последний запрос (`model_served`) — имя в ответе API бывает не то, что запрошено; ответ `/api/ask`
перечисляет модели раунда (`models`).

Ограничение 128 ГБ относится к локальному развёртыванию. По умолчанию — Qwen3.5-122B-A10B (≈62,5 ГБ в Q4)
и рядом gpt-oss-120b (65,2 ГБ в MXFP4): оба укладываются в лимит, локальная установка не проверялась.
GLM-5.3-Flash (≈161 ГБ в Q4) доступна тем же переключателем как самая сильная на банке, но локальному
контуру не соответствует — потому она и не стоит по умолчанию.

## Три обязательных кейса — две минуты

| Кейс | Вопрос сотрудника | Что увидеть |
|---|---|---|
| 1а — ответ есть | «Сколько заявок может быть у одного ПА?» | Ответ текстом регламента; под ним источник «раздел → пункт», по клику — документ с подсветкой |
| 2 — вопрос допускает варианты | «За сколько до подачи нужно инициировать заявку на расчёт?» | Уточнение, какая дирекция; после выбора — один срок и источник выбранного регламента |
| 1б — ответа нет | «В течение какого времени ПА должен отреагировать на заявку 1-го приоритета?» | «В регламентах нет ответа…», карточка запроса с номером и кнопкой «Отправить»; после нажатия запрос появляется в ящике службы качества |
| 3 — служба качества ответила | В ящике службы качества открыть запрос, написать ответ, подписать именем, отправить — и повторить тот же вопрос | Агент отвечает сам; источник — «Ответ службы качества, <имя>, <дата> · запрос № N» |

Ящик службы качества — вкладка правой колонны (на `/qc` она открыта сразу); колонну показывает кнопка
тестовых инструментов в доке под чатом. Вход на стенде фиктивный: почта и пароль заполнены заранее.

## Экономика

- Стоимость запроса считается по журналу вызовов стенда, а не по оценке. Типовой ответ — три вызова
  (решение, текст, судья), уточнение — один. На банке из 38 вопросов: **3 154 токена входа и 224 выхода**
  на вопрос, **≈0,047 ₽ за запрос** по тарифу официального провайдера модели по умолчанию ($0,115 и $0,917
  за 1 млн токенов, Alibaba Cloud, курс ЦБ РФ 82,3130 на 26.11.2026). Расчёт по шаблону организаторов — в материалах сдачи.
- Нагрузка заказчика: 100–300 вопросов в месяц — 4,7–14,0 ₽ в месяц; 100–120 в день — ≈141–169 ₽;
  200 в день — ≈281 ₽.
- Из чего складывается: токены языковой модели; эмбеддинги — 0 ₽ за API (BGE-M3 считается локально,
  ≈2 ГБ памяти на CPU); сервер приложения — существующий. Вне расчёта: интеграции, СУБД,
  аутентификация, сопровождение.
- Изолированный контур: 0 ₽ за токены, стоимость — сервер с GPU; тариф не называем, у заказчика свой.

## Банк вопросов и замеры

Тестовых вопросов и эталонов в задании нет — банк составлен нами (`bench/bank.json`, 38 вопросов: 31 зачётный
и 7 пробных с нестрогим ожиданием). Вопросы не переформулируют требования дословно: «другими словами» и
сокращениями, с условием в вопросе, без контекста. Группы: **A** — отвечает один регламент (11), **B** — регламенты
дирекций отвечают по-разному, нужен уточняющий вопрос (9), **C** — ответа в регламентах нет (8), **D** — пробные (3
зачётных). Для каждого вопроса заданы ожидаемый маршрут, опорный факт (должен быть в тексте или цитате) и какой
вариант выбрать при уточнении. Зачёт — маршрут и факт.

```bash
python tools/bench_run.py http://127.0.0.1:8087 --out bench/out          # банк целиком: замеры.md и замеры.json
python tools/bench_run.py http://127.0.0.1:8087 --model comet-oss         # другая модель каталога стенда
python tools/stab_check.py http://127.0.0.1:8087 --rounds 6 --only B --tz # устойчивость: 6 раундов, частоты маршрутов
python tools/scenarios.py http://127.0.0.1:8087                          # сквозные кейсы задания, 7 проверок
```

Прото­колы прогонов — `bench/results/`: по одной таблице на модель с разбором расхождений. Приборы ходят по HTTP
и подставляют свой адрес в `X-Forwarded-For` — поэтому их нужно запускать на самом сервере стенда (или локально),
снаружи адрес подменить нельзя и все вопросы уйдут с одного адреса.

## Ограничения прототипа

- Не реализовано: коннектор к Confluence и загрузка документов через интерфейс; настоящая почта (SMTP
  с TLS и аутентификацией) и чтение агентом ящиков; настоящая аутентификация — вход демонстрационный,
  сотрудники разделены по адресу сети (за одним NAT — одна система); права доступа; учёт версий и дат
  действия документов. Ответ службы качества хранится отдельной записью базы знаний: найденные пункты
  уходят с вопросом в письме службы качества, но явной ссылки на пункт регламента у записи нет.
- Не замерялось: корпус больше четырёх регламентов (у заказчика около 300), нагрузка, локальный запуск
  языковой модели.
- Решение модели недетерминировано: модель по умолчанию Qwen3.5-122B-A10B на одном и том же коде даёт
  от 21 до 24 совпадений из 31 — меняется число уточняющих вопросов (у запасной GLM-5.3-Flash разброс 27–31).

Актуальность документов в прототипе не вычисляется: в корпусе задачи по одной действующей редакции
каждого регламента, полей версий и дат нет. Предлагаемая для внедрения логика: источник документов —
активная версия Confluence; в поиск идут только действующие редакции; версия и дата показываются в адресе
источника; новая редакция архивирует прежнюю и помечает её записи базы знаний «нужна проверка».

## Запуск

```bash
pip install -r requirements.txt
ollama pull bge-m3                                 # эмбеддинги; языковая модель — облачная по ключу из .env или свой OpenAI-совместимый сервер
python -m app.engine                                  # построить векторный индекс (около минуты)
cp .env.example .env                                 # заполнить ключ, если нужна облачная модель
python -m uvicorn app.web:app --port 8080             # стенд: / полный вид, /user чат, /qc служба качества, /analytics статистика
python -m unittest discover -s tests                 # 176 тестов (нужен локальный сервер эмбеддингов)
```

В Docker — стенд и отдельный сервер эмбеддингов (BGE-M3 на CPU, около 2 ГБ памяти):

```bash
cp .env.example deploy/.env                           # заполнить ключ, если нужна облачная модель
docker compose -f deploy/compose.yml --env-file deploy/.env up -d --build
curl http://127.0.0.1:8087/api/health                 # готово, когда "ok": true
```

Первый старт без готового векторного индекса считает векторы корпуса — до 10 минут на CPU.
За reverse proxy (Caddy, nginx) стенд включается в сеть прокси вторым файлом
`deploy/compose.proxy.yml` — имя сети задаётся переменной `PROXY_NETWORK`, прокси ходит
в контейнер `iikuznica-stand:8080`.

```
app/       код решения
  docx.py      чтение DOCX: абзацы, списки с нумерацией, таблицы

  search.py    словесный канал: леммы, аббревиатуры, глоссарий, BM25; слияние каналов

  agent.py     цикл: найти → решить → проверить → ответить, уточнить или «нет ответа»

  ratelimit.py лимит вопросов в час с одного адреса
  service.py   служба: диалог, запрос в службу качества, пополнение базы знаний
  store.py     SQLite: сессии, вопросы, запросы, письма, журнал вызовов модели
  mail.py      отправка писем по SMTP (тестовый сервер, без TLS и аутентификации)
  web.py       FastAPI: страницы /, /user, /qc, /analytics и /api/*
  llm.py       клиент модели: повторы, запасная модель, счёт токенов
  config.py    настройки из окружения
bench/     банк вопросов (38: 31 зачётный и 7 пробных) и протоколы прогонов
tools/     bench_run.py — прогон банка и отчёт; stab_check.py — устойчивость за N раундов;
           scenarios.py — сквозные кейсы задания по HTTP; build_terms.py — словарь терминов
static/    оформление стенда (без сборки и внешних зависимостей)
deploy/    compose.yml — стенд и сервер эмбеддингов; compose.proxy.yml — включение за reverse proxy
data/      регламенты заказчика (обезличены), глоссарий, словарь терминов
tests/     тесты
karkas/    наработка до спринта — каркас, датирован 09.10–16.11.2026; не конкурсная разработка
```
