# Агент ответов на вопросы по корпоративным регламентам

Хакатон «ИИкузница» 2026 · задача №1 · трек «Аналитик данных».

Агент отвечает сотрудникам на вопросы по регламентам **строго текстом регламентов** и показывает
источник — раздел, пункт, подпункт. Если ответа нет — не выдумывает, а заводит запрос в службу
качества. Если вопрос допускает разные ответы — уточняет. После ответа службы качества — пополняет
базу знаний.

## Что уже работает

- **Загрузка регламентов.** DOCX разбирается на разделы, пункты и подпункты; номера пунктов
  восстанавливаются из разметки Word. Каждый абзац получает адрес и дословный текст.
- **Поиск.** Два канала — по словам (BM25, леммы, глоссарий заказчика) и по смыслу (эмбеддинги) —
  слитые обратными рангами. Отдельно выдаётся лучший ответ каждого регламента: так видно, где
  дирекции отвечают на один вопрос по-разному.
- **Агент.** Модель решает: ответить, уточнить или признать, что ответа нет. Решение проверяется кодом:
  в ответ проходят только найденные фрагменты; если регламенты отвечают по-разному, агент уточняет.
- **Тесты.** 49 проверок: инварианты разбора (каждая цитата дословно есть в исходнике), вопросы
  сотрудника другими словами (нужный пункт в топ-3 у всех 16), логика агента и повторов модели.

## Модели

Обе — открытые, с лицензией MIT: допускают локальное использование и дообучение, укладываются
в 128 ГБ видеопамяти в квантовании Q4 (19 ГБ и 1.2 ГБ).

| Роль | Модель | Лицензия и веса |
|---|---|---|
| Языковая модель | GLM-4.7-Flash | <https://huggingface.co/zai-org/GLM-4.7-Flash> |
| Эмбеддинги | BGE-M3 | <https://huggingface.co/BAAI/bge-m3> |

Сервер модели — любой OpenAI-совместимый: локальный (Ollama) или облачный API официального
провайдера. Переключение — переменными окружения, ключи только в окружении.

## Запуск

```bash
pip install -r requirements.txt
ollama pull bge-m3 && ollama pull glm-4.7-flash      # локальные модели
python -m app.engine                                  # построить векторный индекс (около минуты)
python -m unittest discover -s tests                 # 49 тестов
```

## Структура

```
app/       код решения
  docx.py      чтение DOCX: абзацы, списки с нумерацией, таблицы
  ingest.py    регламент → разделы → пункты → адресуемые абзацы
  search.py    словесный канал: леммы, аббревиатуры, глоссарий, BM25; слияние каналов
  vectors.py   поиск по смыслу через OpenAI-совместимый сервер эмбеддингов
  engine.py    сборка движка и кэш векторного индекса
  agent.py     цикл: найти → решить → проверить → ответить, уточнить или «нет ответа»
  llm.py       клиент модели: повторы, запасная модель, счёт токенов
  config.py    настройки из окружения
data/      регламенты заказчика (обезличены), глоссарий, словарь терминов
tests/     тесты
karkas/    наработка до спринта — каркас, датирован 09.10–16.11.2026; не конкурсная разработка
```
