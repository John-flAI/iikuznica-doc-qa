# Агент ответов на вопросы по корпоративным регламентам

Хакатон «ИИкузница» 2026 · задача №1 · трек «Аналитик данных».

Агент отвечает сотрудникам на вопросы по регламентам **строго текстом регламентов** и показывает
источник — раздел, пункт, подпункт. Если ответа нет — не выдумывает, а заводит запрос в службу
качества. Если вопрос допускает разные ответы — уточняет. После ответа службы качества — пополняет
базу знаний.

## Что уже работает

- **Загрузка регламентов.** DOCX разбирается на разделы, пункты и подпункты; номера пунктов
  восстанавливаются из разметки Word. Каждый абзац получает адрес и дословный текст.
- **Поиск.** Два канала — по словам (BM25, леммы, глоссарий заказчика) и по смыслу (эмбеддинги) —
  слитые обратными рангами. Отдельно выдаётся лучший ответ каждого регламента: так видно, где
  дирекции отвечают на один вопрос по-разному.
- **Агент.** Модель решает: ответить, уточнить или признать, что ответа нет. Решение проверяется кодом:
  в ответ проходят только найденные фрагменты; если регламенты отвечают по-разному, агент уточняет.
- **Текст ответа.** Модель пишет связный ответ только по выбранным пунктам; код сверяет числа и
  сокращения с пунктами, вторая проверка — модель-судья. Не прошло — ответ показывается пунктами дословно.
- **Тесты.** 71 проверка: инварианты разбора (каждая цитата дословно есть в исходнике), вопросы
  сотрудника другими словами (нужный пункт в топ-3 у всех 16), логика агента и повторов модели,
  служба качества, маршруты стенда.

## Модели

Все — открытые, с лицензией MIT: допускают локальное использование и дообучение, укладываются
в 128 ГБ видеопамяти в квантовании Q4.

| Роль | Модель | Параметров | Видеопамять в Q4 | Лицензия и веса |
|---|---|---|---|---|
| Языковая модель | GLM-4.7-Flash | 31,2 млрд | ≈18 ГБ | MIT · <https://huggingface.co/zai-org/GLM-4.7-Flash> |
| Эмбеддинги | BGE-M3 | 0,6 млрд | 1,2 ГБ | MIT · <https://huggingface.co/BAAI/bge-m3> |

Сервер модели — любой OpenAI-совместимый: локальный (Ollama) или облачный API официального
провайдера. Переключение — переменными окружения, ключи только в окружении.

Две вещи, которые мы проверили и о которых стоит знать (27.11.2026):

- В облаке официального провайдера GLM-4.7-Flash бесплатна, но бывает перегружена — до половины
  вызовов отклоняется кодом 429 короткими сериями. Клиент (`app/llm.py`) повторяет запрос часто и
  ненадолго, ответ при этом приходит за 2–6 секунд. `/api/health` показывает и имя из настроек
  (`model`), и модель, которая реально ответила на последний запрос (`model_served`).
- GLM-4.5-Air (110,5 млрд параметров, ≈57 ГБ в Q4, MIT) тоже проходит по требованиям и работает
  с этим кодом без изменений. Но в облаке запрос с именем `GLM-4.5-Air` провайдер обслуживает
  моделью GLM-5.3-Flash (≈163 ГБ в Q4 — не проходит по лимиту), поэтому на стенде она не используется.

## Запуск

```bash
pip install -r requirements.txt
ollama pull bge-m3 && ollama pull glm-4.7-flash      # локальные модели
python -m app.engine                                  # построить векторный индекс (около минуты)
cp .env.example .env                                 # заполнить ключ, если нужна облачная модель
python -m uvicorn app.web:app --port 8080             # стенд: / полный, /user чат, /qc служба качества
python -m unittest discover -s tests                 # 78 тестов
```

В Docker — стенд и отдельный сервер эмбеддингов (BGE-M3 на CPU, около 2 ГБ памяти):

```bash
cp .env.example deploy/.env                           # заполнить ключ, если нужна облачная модель
docker compose -f deploy/compose.yml --env-file deploy/.env up -d --build
curl http://127.0.0.1:8087/api/health                 # готово, когда "ok": true
```

Первый старт без готового векторного индекса считает векторы корпуса — до 10 минут на CPU.
За reverse proxy (Caddy, nginx) стенд включается в сеть прокси вторым файлом
`deploy/compose.proxy.yml` — имя сети задаётся переменной `PROXY_NETWORK`, прокси ходит
в контейнер `iikuznica-stand:8080`.

## Структура

```
app/       код решения
  docx.py      чтение DOCX: абзацы, списки с нумерацией, таблицы
  ingest.py    регламент → разделы → пункты → адресуемые абзацы
  search.py    словесный канал: леммы, аббревиатуры, глоссарий, BM25; слияние каналов
  vectors.py   поиск по смыслу через OpenAI-совместимый сервер эмбеддингов
  engine.py    сборка движка и кэш векторного индекса
  agent.py     цикл: найти → решить → проверить → ответить, уточнить или «нет ответа»
  service.py   служба: диалог, запрос в службу качества, пополнение базы знаний
  store.py     SQLite: сессии, вопросы, запросы, журнал вызовов модели
  web.py       FastAPI: страницы /, /user, /qc, /analytics и /api/*
  llm.py       клиент модели: повторы, запасная модель, счёт токенов
  config.py    настройки из окружения
static/    оформление стенда (без сборки и внешних зависимостей)
deploy/    compose.yml — стенд и сервер эмбеддингов; compose.proxy.yml — включение за reverse proxy
data/      регламенты заказчика (обезличены), глоссарий, словарь терминов
tests/     тесты
karkas/    наработка до спринта — каркас, датирован 09.10–16.11.2026; не конкурсная разработка
```
