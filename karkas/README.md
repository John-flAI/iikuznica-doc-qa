# Каркас прототипа «ИИкузницы» (этап А-9)

**Принцип:** ноль зависимостей — только стандартная библиотека Python. На
хакатоне 48 часов тратятся на задачу, а не на окружение. Проверено 09.10:
сервер поднялся, вопрос «через сколько вернутся деньги за возврат?» получил
ответ с опорой на демо-документ регламента.

## Запуск
```
python app.py                      # витрина + API на http://127.0.0.1:8765
APP=... TG_TOKEN=... python bot.py # (опционально) TG-интерфейс агента
```

## Что внутри
- **Оркестратор** (`llm_answer` в app.py): вопрос → поиск опоры в базе →
  ответ. Сейчас отдаёт честный черновик; точка подключения LLM помечена.
- **RAG на TF-IDF** (stdlib): add_doc/search — до 5–10 тыс. документов хватит;
  на хакатоне при времени заменить на эмбеддинги (адаптер один — tokenize/search).
- **Витрина**: одна страница, тёмный стиль, добавление документов + чат.
- **TG-бот** (bot.py): длинный опрос Bot API, пересылает вопрос в /api/ask.

## Чек-лист подключения в первые 4 часа хакатона
1. `llm_answer()`: вставить адаптер к модели (живой образец — PROJECTS/tquote/
   probe.py: api.z.ai/api/anthropic, ключ из сейфа; на хакатоне — их облачные мощности).
2. Под задачу: заменить демо-документы на данные задачи, добавить 2–3 поля в
   витрину (загрузка файла, кнопка действия).
3. Метрики для питча: считать время ответа агента и «документов в опоре» —
   жюри любит числа.
4. TG-токен у BotFather создаёт владелец (гейт).

## Что сознательно НЕ в каркасе (чтобы не тащить лишнего)
авторизация, база данных (json в памяти + периодический дамп в файл
добавляется за 15 минут при нужде), стили за пределами одной страницы.
