# «Канцелярист» — каркас прототипа (акт. 22.10)

Агент входящих документов малого бизнеса: счёт/договор/акт/письмо загружается PDF,
агент определяет тип, вытаскивает реквизиты **с цитатой-источником у каждого поля**,
сверяет с реестром компании, готовит черновик ответа и оставляет решение человеку.
Паттерн переиспользует каркас Островка: без LLM-ключа всё работает детерминированно.

Позиция против галлюцинаций: каждое утверждение — с цитатой (файл, страница, строка);
«нет в базе» — валидный ответ; исходящие — только черновики, отправляет человек.

## Запуск

```bash
pip install -r requirements.txt
python demo/make_demo_pdfs.py        # 10 демо-PDF → demo/пакет/
python -m uvicorn src.main:app --port 8002
# витрина: http://127.0.0.1:8002  (туда же перетащить PDF)
```

Самопроверка конвейера без сервера: `python demo/проверка.py`
(ожидание: 10/10 разобрано, типы верны, ровно 2 ловушки найдены).
Замечание: у А-9 (root app.py) свой порт 8765 — каркасы не мешают друг другу.

## Демо-сценарий для жюри (3 минуты)

1. В витрину перетаскивается пакет из 10 PDF (счета, договор, акт, письма, реклама).
2. Лента: у каждой карточки тип, контрагент, сумма, статус; у 2 документов — «⚠ расхождения».
3. Ловушка №1 (`04_schet_romashka_046.pdf`): настоящий поставщик, но **подменён р/с** —
   агент ловит и блокирует платёж («НЕ платить без проверки»), ставит эскалацию.
4. Ловушка №2 (`05_schet_kanc_129.pdf`): знакомое название, **ИНН отличается на цифру** —
   агент сверяет по реестру, а не «по памяти».
5. Черновик ответа у каждого документа с цитатами-источниками; человек жмёт
   «Согласовать / Исправить / Эскалировать» — всё в журнал решений (SQLite).
6. Письмо-запрос про сертификаты: в базе нет → агент отвечает «нет данных», не выдумывает.

## Метрики на демо-пакете (замер 22.10)

- 10/10 документов разобраны, типы определены верно;
- 88 полей извлечено (в среднем 8,8/документ), ~124 мс/документ (детерминированный режим);
- ловушки 2/2 найдены, ложных срабатываний 0;
- 0 выдуманных фактов: у каждого поля и черновика — источник.

## Структура

```
karkas/
├── src/
│   ├── main.py          FastAPI: /upload, /api/docs, /api/docs/{id}/decision, витрина
│   ├── pipeline.py      конвейер одного документа
│   ├── classify.py      тип документа (маркер-слова, без LLM)
│   ├── requisites.py    реквизиты по регэкспам; каждое поле с {страница, цитата}
│   ├── registry.py      реестр (контрагенты/договоры) и сверка → расхождения
│   ├── drafts.py        черновики ответов по типам + честное «нет данных»
│   ├── llm_adapter.py   опциональная полировка тона (env LLM_API_KEY, иначе выкл.)
│   ├── store.py         SQLite: карточки + журнал решений (karkas/data/)
│   └── vitrina.py       демо-страница (один HTML, без сборки)
├── src/data/            реестр демо-контрагентов и договоров (источник истины для сверок)
└── demo/
    ├── make_demo_pdfs.py  генератор пакета (reportlab, кириллица — системный TTF)
    ├── проверка.py        самопроверка конвейера на пакете
    └── пакет/             10 PDF (8 чистых + ловушки 04 и 05)
```
